# Current architecture

The npm workspace has two packages. Core validates gateway reads and runs fixed private scenario definitions. CLI calls core; it has no arbitrary endpoint, user-supplied script or public mutation option. Private signing state stays in ignored .local/.

- rpc.ts: five allowlisted public read methods, native HTTPS fetch, redirect rejection, per-read 15-second deadline and 1 MiB response ceiling, JSON-RPC ID/error validation. No retries or mutations.
- schema.ts: actual inspected sidecar wire types projected to safe fields; protocol quantities stay hex. Payloads, signatures, calldata, receipt logs and arbitrary error/detail strings are not exported. Waiver status is derived from detail text before discarding it.
- inspect.ts: captures chain/explorer identity around transaction admission, lifecycle and receipt reads. Compares identities/frame counts and detects observable history discontinuity. Captures are sequential, not atomic snapshots; history already lost before the first read cannot be recovered.
- artifact.ts: generated UUID filenames, workspace-contained observation reports and exclusive file creation.
- scenario.ts: validated source-backed scenario definitions, sequential real actions and explicit result precedence. FAIL dominates missing prerequisites; BLOCKED branches prevent a whole-suite PASS. The seed names action order, not the random private keys.
- local/codec.ts: official profile, frame builder, signatures and wire encoder; no custom transaction serialization. The payer fixture uses a distinct EOA with its own payment signature, not a deployed paymaster contract.
- local/fixture.ts: checks image provenance/genesis template, generates fresh private keys, creates internal Docker networking and bounded processes, verifies two-process admission or four-process mining isolation, then removes owned containers/network. Private keys, generated config and diagnostic logs remain under .local/ with restrictive modes. Unique directories reject accidental run-ID reuse.
- local/mining.ts: offline pinned genesis/validator generation, fresh mnemonic and JWT, explicit funded-account/fork/predeploy validation and restrictive file modes. Lighthouse beacon and validator processes drive staged forks; the mining smoke test uses automatic sidecar bundling. This module does not implement consensus or call privileged relay methods.
- evidence.ts: AsyncLocalStorage isolates bounded per-run RPC journals. Method-specific output schemas strip payloads/logs/arbitrary detail; receipt/lifecycle values remain node observations, while waived/balance-enforcement flags are normalized from text. Request digests do not execute or preserve payloads. Readiness recovery is channel-specific. Overflow/projection failures are explicit and prevent PASS. Legacy reports retain no invented journal.
- local/rpc.ts: runtime allowlist, fixed Bun fetch program executed via execFile argument arrays inside the owned sidecar container. No shell, no user script, no public endpoint, no published ports. Responses/time are bounded. This CLI-only transport must never become a public web API.
- local/lifecycle.ts: bounded fork readiness, receipt and explorer polling, transaction identity checks and ordinary signed EIP-1559 transfers. Canonical nonce conversion is guarded against unsafe JS integer conversion. No privileged relay or bundling-control method is exposed.
- local/scenarios.ts: actual mined keyed-sequence and payer-balance actions. Source-specific cancellation markers distinguish balance enforcement from an earlier revalidation failure. Entry timestamps remain hex and use the source's submittedTime/lastUpdatedTime ordering fallback.
- report.ts: strict scenario schema, UUID paths, exclusive writes, symlink containment, regular-file-only bounded reads, no-follow leaf opens on Linux, size limits, SHA-256 checks before semantic parsing and escaped Markdown. Cross-field validation checks aggregate verdict, definition identity, action completeness/order/uniqueness and chronology. Checksum is not an authenticity attestation; exact replay remains future work.
- evidence-check.ts: offline selected-output consistency checks against step cursor ranges. Rechecks supported receipts/statuses/timestamp order and cost arithmetic with BigInt, reports missing evidence and contradictions separately, and lists unreevaluated steps. It cannot reconstruct redacted request semantics or authenticate saved claims.
- replay.ts: private saved-run requirements, exact current definition matching, fresh-state rerun planning and action-verdict/stable-environment comparison. It never executes saved command text and does not restore historical state. Missing environment fields in a failed rerun remain visible as differences.
- CLI: doctor, inspect, versions, help, scenarios, run --local [--mine] report --format json|md replay --plan or --local [--mine], offline compare <baseline-id> <rerun-id>, evidence <run-id>, and check-evidence <run-id>. JSON is native output; use npm run --silent when piping it. Native exit 2 means invalid arguments, 3 means BLOCKED, 1 means failed/inconclusive/unavailable evidence or file errors, and 0 means the command completed its declared checks. npm/WSL wrappers can normalize nonzero exits; integration tests check the native process status directly.

The bootstrap scripts/probe-devnet.mjs remains independently usable without installing npm dependencies. It is a setup diagnostic, not a second scenario/report implementation.

Tests use injected transports or copies of a real captured observation to check error handling and evaluation. Test outputs are never published as live evidence. Artifact tests create isolated /tmp/aftershock-* files/directories. CLI --save writes ignored reports in the Linux checkout.

The CLI's non-mining fixture exercises admission/replacement and remains BLOCKED for omitted mining. --mine runs both original scoped lifecycle sequences against fresh staged-fork chains with manual sidecar bundling. test:mining separately checks automatic sidecar relaying. There is no web server, UI or exact replay. Resource labels/unique names scope teardown; fresh genesis/key state prevents cross-run account collisions. Private scenario-error logs aid diagnosis without leaking server text into reports. Cached-image-only startup prevents unapproved downloads.
