## Separate keyed TTL expiry/refresh case

keyed-replacement-ttl extends the keyed scenario family; it is not a third original suite. It uses actual sidecar admission against the non-mining private chain and verifies useropsTTL=30. Base fees are 2000000000/1000000000 wei. The same 2100000000/1050000000 candidate is rejected before expiry and accepted afterward, while the old identical hash remains DUPLICATE even after expiry. Replacement removes the old active hash, records replaced history and advances lastUpdatedTime by more than 30000 milliseconds. A subsequent 2150000000/1075000000 candidate is rejected during the refreshed window; the accepted entry remains New with unchanged timestamp.

[Reviewed real TTL capture](evidence/keyed-replacement-ttl.json) records all ten declared actions plus cleanup, the observed node timestamps and projected RPC responses. No state transition was simulated in an expected-state model. No block production, inclusion, exact expiry boundary or terminal-state exemption is claimed. check-evidence explicitly returns INSUFFICIENT for this case because no offline TTL checker is implemented.

## Cancelled predecessor extension

cancelled-replacement extends the shared-payer/keyed lifecycle coverage and requires --local --mine. It admits a sponsored EOA transaction and checks live duplicate/below-bump rejection. A mined 800000000000000-wei payer drain plus gas must make its observed balance lower than the simulated maximum cost; the actual entry must become Cancelled with dropped history. A real funding transfer restores affordability, after which a different 2100000000/2100000000-wei candidate is submitted below the old 10% fee threshold. A second drain/restoration allows identical signed resubmission. Both readmissions must be within the 300-second window measured from actual cancellation lastUpdatedTime, excluding TTL expiry as the explanation.

Active reactivation and explorer outcome are separate checks. The pinned same-hash explorer edge must remain a scenario FAIL if reproduced; a regression test passing on that exact finding does not make the protocol case PASS. Unknown errors, additional failures, incomplete recording or absent prerequisites fail the regression harness. Four ordinary canonical transfer receipts are required; no frame inclusion is claimed. OnChain/Finalized/Reverted, Pending/Submitted behavior, exact TTL boundary and exact replay remain outside this case. Actual execution and capture provenance are recorded in ENVIRONMENT.md.

The final native integration test passed by verifying the exact known finding: [complete actual capture](evidence/cancelled-replacement.json), run 64305eac-6073-4f35-ba81-50a64fe8bc75, has 112 entries, zero omissions and complete recording. Its scenario verdict is FAIL, with explorer-reactivation-consistency reporting active New versus explorer replaced. All other substantive actions pass; the derived whole-case mined-state-transition summary is INCONCLUSIVE because it includes the failed check. Both reacceptances were within TTL (6283/4325 milliseconds after cancellation), and all four canonical transfers succeeded. No full-scenario PASS is claimed.
