# Threat model

This is a devnet research tool, not an auditor's proof of safety. Source-backed proposed invariants are in [PROJECT_SPEC](PROJECT_SPEC.md).

| Boundary | Risk | Required control before implementation |
| --- | --- | --- |
| Shared devnet | Disrupting other participants | Only normal funded workshop transactions and bounded reads; no stress, reputation/admin mutations or privileged relay calls |
| Isolated stack | A localhost proxy may still point at shared infrastructure | Verify process ownership, chain configuration, upstream RPCs, peer isolation and loopback bindings before stateful tests; localhost alone is insufficient |
| Signing state | Secrets in logs, reports or Git | Fresh throwaway keys, faucet funding, private ignored state, allowlisted exports and redaction; never shared genesis keys or personal wallets |
| RPC responses | Malformed, huge, stale or dishonest data | Validate schemas and quantities, response size/time bounds, explicit source/channel; a response is node-reported evidence, not independent cryptographic proof |
| Version identity | Applying a source rule to another build | Record source pins separately from observed commit; unknown identity yields INCONCLUSIVE for version-dependent assertions |
| Explorer history | Restart or eviction hides lifecycle actions | Capture bootId and sequence bounds before/after; resync with explicit gaps, preserve opaque cursors; skipped and waived checks are not independent enforcement |
| Execution | Admission/inclusion mistaken for success | Inspect actual per-frame receipts and status; pending receipt absence is not a failure |
| Replay/report files | Traversal, script injection, forged findings | Validated IDs, containment checks, immutable exclusive writes, integrity checks; no arbitrary payload execution; local reset snapshots required for deterministic replay |
| Future UI | Remote shell access or credentials exposed | Local read-only report browsing; no deployed transaction runner or shell interface; escape untrusted content |

Trusted inputs are our pinned inspected source and explicit fixture definitions. Live node metadata is an assertion by that node. The public gateway exposes no source commit, so its responses cannot establish the pinned implementation's invariants. Private mined tests now cover New-entry solvency eviction and keyed predecessor/next-sequence inclusion. Submitted-entry and terminal/TTL exceptions remain untested.

Paymaster accounting requires the balance callback; executor.ts wires it in at the inspected commit. The suites inspect actual TTL and reject expired replacement preconditions. --mine selects staged consensus with manual bundling, which still reconciles blocks at the pinned source. Ordinary canonical transactions drive the controlled state changes. Non-mining runs explicitly block those actions.

Diagnostic exports validate and allowlist explorer/config fields, discard untrusted server error text and fail on inconsistent chain IDs. They do not authenticate the operator's claims or provide a signed attestation. Unit-test transports are injected only through module imports, never through CLI options; unit tests do not save mock results as public evidence.

Private fixtures use Docker internal networks, no published ports, disabled execution-client P2P, unique names/labels, resource limits and freshly generated keys. All shared funded EOAs are removed from the upstream genesis template before funding our fresh accounts. No shared genesis credentials are used. Private state/logs remain ignored and mode-restricted; teardown removes owned containers/network. Docker daemon access is a trusted local CLI capability and must never be exposed to the future web viewer.

The pinned upstream sidecar dependency audit has advisories; Docker isolation is a containment boundary, not proof those dependencies are safe. No public deployment is appropriate. Report SHA-256 checks detect accidental modification, not malicious authors who can recompute checksums. Fresh-account reruns are not exact snapshot replay.

Mining adds a pinned offline genesis generator and pinned Lighthouse beacon/validator image. All validator mnemonics and execution keys are freshly generated. Insecure-format test keystores, JWT and generator tracing remain under private ignored .local/; never export generator metadata or logs wholesale. Runtime EL P2P and CL discovery are disabled, all four processes share only their owned internal network and no ports are published. The generator has network=none and is tracked for teardown. The sidecar's own automatic relayer is trusted local upstream behavior; Aftershock's transport still cannot invoke its privileged submission method.

Agents require approval before dependency installation or external deployment. Existing disposable local tests are authorized; fixture creation disables image pulls. Public/private JSON-RPC readers reject ambiguous result+error envelopes. Private negative assertions require the inspected method, numeric code and message family. Reports reject inconsistent verdicts, missing PASS actions, duplicate/out-of-order steps and invalid chronology. Checksums still do not authenticate an author. Scenario diagnostics remain private; arbitrary error text is not exported.

Fresh-state rerun accepts only validated workspace-local private reports with the current built-in definition. It never executes stored reproducer text or arbitrary payloads. Explicit --local authorizes a new disposable fixture; --mine must match the baseline. Historical hashes, balances and timing are not reproduced or compared. Matching verdicts do not prove identical execution, and matching unavailable evidence cannot become PASS. A malicious local report author can still forge observations/checksums; this is not independent verification.

The offline compare command only reads saved reports; exit 0 means a comparison was exported, not that either invariant passed. Linux report reads use nonblocking, no-follow opens, require regular files and cap allocation/reads at 1 MiB plus one overflow byte. This avoids FIFO waits and oversized reads after file growth. These controls do not authenticate a local author or provide protection against every filesystem race involving a trusted report directory.


Projected RPC evidence adds no new RPC methods or public mutations. The collector observes only the existing fixed private transport. It exports allowlisted output fields, normalized failure families, request digests and supported hash references, never private fixture data or raw requests. Per-run asynchronous scope prevents concurrent runs from sharing journals. Strict report validation checks method projections, recording counters, chronology and step cursors; inconsistent/incomplete recording cannot claim PASS. Legacy evidence is absent, not synthesized. Complete recording does not authenticate a node/author or make observations atomic. Recorded readiness transport failures can recover only after a later same-channel chain-9 response; arbitrary required scenario failures cannot be waived this way.


Offline check-evidence compares selected stored summaries with recorded response projections. CONSISTENT is scoped output consistency, not a source-authenticated invariant PASS, proof of correct signing/request parameters or independent review. Complete recording plus a stored PASS and compatible saved metadata are prerequisites, not cryptographic attestations. Missing receipts remain insufficient. A malicious author who coordinates edits to both the summaries and journal can evade this check. Unsupported actions and redacted semantics are explicitly listed; original files are never rewritten. Scenario definitions now reject duplicate actions and reserved metadata step IDs to avoid false action-completeness claims.
