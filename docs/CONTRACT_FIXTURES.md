# Contract and fixture decision

Audited 2026-11-06 against the Version 2 master requirements. **CONTRACT DECISION: new Solidity is NOT REQUIRED for the two currently declared suites.** Their shared payer is a fresh EOA, not a deployed contract paymaster. Contract-based sponsorship predicates remain outside current coverage. The additional staked-storage demonstration deploys existing pinned upstream artifacts; no new Solidity or local rebuild is claimed.

The main contracts inherit @forshtat/hegota-support 0.0.1, Devnet.ERC8421_WORKSHOP. Its constructor creates opcode helper contracts: seven nonempty helper implementations in this profile imply starting nonce 8, rather than 0/1. This is a source expectation; the new sponsor run separately observed wallet nonce 8 after deployment. Any future deployment must read actual code, balance and nonce from its own chain. Creation value is the supported funding path. An ordinary ETH transfer invokes validation fallback outside a Frame Transaction and must not be assumed to work.

Workshop step_3_tx_paymaster deploys the sponsor with creation funding and reads balances; step_4_wallet_deploy deploys the owner wallet; step_12_tx_keyed_nonces reads nonce-manager slots and the wallet account nonce before/after transactions. Those existing paths suffice for their demonstrated contract behavior. The configured staking registry address is configuration, not proof of deployment on Aftershock's private genesis; buildStakeTx targets addStake(uint32) payable. Neither original EOA suite stakes; the additional staked-storage-boundary scenario does.

The sidecar test/e2e/helpers.ts also contains primitive test-only wallet/paymaster creation bytecode with unconditional approval. Its sharedSenderPool fixture uses nonce/recent-root primitives. These are not production access policies and are not vendored. test/e2e/ethrex-devnet.sh was inspected, not launched: its published ports and shared genesis credentials do not meet our isolation rules. Our existing fresh-account internal Docker fixture is retained. The P2P.md sentinel 0x00000000000000000000000000000000000000aa is not a deployed ERC-4337 EntryPoint; these tests never use UserOperation or handleOps.

## Native integration verification

`npm run test:fixtures` reuses the existing isolated EIP-8141-aware ethrex/sidecar mining stack. It checks the official nonce-manager address 0x0000000000000000000000000000000000008250 has runtime 0x60006000fd, matching ethrex crates/vm/system_contracts.rs, installed at Hegota rather than genesis.alloc. This runtime rejects direct calls; protocol processing updates its storage. Fresh sender/payer addresses must have empty code.

The test reads keyed slots 1/2 and ordinary sender nonce, admits a genuine keyed transaction through the sidecar, submits it canonically, checks successful per-frame receipts and included lifecycle, and rereads slots/nonce. It also mines a real one-wei payer transfer and checks native balance decreases. RPC evidence records runtime length/digest and storage words; it excludes signing payloads and private keys. This is additional protocol/EOA fixture coverage, not deployment of a workshop Solidity wallet/paymaster, a third original scenario, full raw tracing or an independent audit. Actual execution results are recorded in [ENVIRONMENT](ENVIRONMENT.md).

## Keyed TTL extension

The keyed-replacement-ttl case also requires no new Solidity. Its 30-second replacement TTL is offchain private-node configuration verified through skandha_config; entry timestamps and statuses are never edited. admit-base, reject-fee-before-ttl, reject-duplicate-after-ttl, accept-fee-after-ttl and reject-fee-after-refresh use genuine eth_sendFrameTransaction. confirm-live-predecessor and wait-for-ttl use eth_getFrameTransactionByHash plus skandha_frameTransactionStatus around a bounded local wait. verify-ttl-replacement uses observed entry timestamps, old-entry absence and skandha_explorer_getTransaction replaced history. verify-active-replacement checks entry identity/timestamp/status and rejected-hash absence. explorer-continuity and fixture-cleanup retain the existing operations. This is admission-only coverage and deploys no contract.

## Cancelled predecessor extension

No new Solidity is required: the same fresh EOA payer supports both actual drains and restorations. admit-base, reject-live-duplicate, reject-live-below-bump, accept-cancelled-below-bump, resubmit-cancelled-identical, reject-reactivated-duplicate and reject-reactivated-below-bump use eth_sendFrameTransaction. drain-for-cancellation, drain-for-recancel, restore-payer and restore-payer-again use ordinary signed eth_sendRawTransaction, successful eth_getTransactionReceipt, balance reads and ethrex_simulateFrameTransaction cost boundaries. observe-cancelled and observe-recancelled combine dropped explorer history with actual Cancelled status and entry metadata. confirm-terminal-window and confirm-resubmission-window verify held Cancelled metadata and non-expired TTL windows. verify-terminal-replacement checks old-hash removal, timestamps and replaced history. verify-reactivation checks the same hash is active New within TTL; explorer-reactivation-consistency separately checks its admission outcome. explorer-continuity, mined-state-transition and fixture-cleanup retain the existing operations. This covers Cancelled only, not all terminal states or contract-based paymasters.

## Verified reuse: staked storage boundary

The 2026-11-06 native integration run `1d533d00-1d6c-411a-9131-5d4a242d3e0f` deployed the sidecar-pinned `STAKING_REGISTRY_INIT_CODE` from `deploy/predeploy/src/protocols/staking-registry-deployment.ts`, plus workshop-pinned Foreign and ViolatingWallet creation artifacts. CREATE-address derivation, successful receipts and actual nonempty runtime code were checked: registry 1259 bytes, Foreign 76 bytes, wallet 2027 bytes. The wallet was creation-funded with 0.05 ETH and owned by a fresh private fixture account.

The wallet's clean signed Frame Transaction called the real registry `addStake(uint32)` with 0.012 ETH and delay 86400 seconds. The configured minimum delay was 0; the chosen delay is not claimed as a network minimum. Observed stake, registry balance, wallet nonce/balance, successful frames and subsequent foreign-storage admission establish the transition. All deployment/account keys remain private under ignored Linux `.local/`. No static genesis allocation is presented as a deployment. See `docs/evidence/staked-storage-boundary.json` for the actual outputs and source pins.

The registry source comment describes a compiler version, while embedded bytecode metadata differs; this milestone reuses the pinned artifact and verifies actual execution. It does not claim compiler reconstruction, source-to-bytecode equivalence or a fresh contract build. Existing artifacts are sufficient for this scenario; a custom paymaster policy remains outside scope.
